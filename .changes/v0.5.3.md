## [0.5.3] - 2026-11-12 [security]

Dockmesh 0.5.3 is a security patch release. Every path that deploys from a stack's files now checks all of them, including the auto-scaler, scaling, rolling updates and image updates, so a container that can write its own stack directory can no longer change what Dockmesh deploys without a confirmation. The setup wizard no longer reopens on an installation that was already set up. Upgrading is recommended; read the upgrade notes.


### Changed

- A deploy of a stack with a default environment override asks first and names the override file; scale and rolling update ask before they use stack files changed outside Dockmesh; the stack page shows when auto-scaling is paused and why

### Fixed

- Replicas the auto-scaler adds use the stack directory for relative bind mounts, like a manual scale, instead of a temporary copy that is deleted right after

### Security

- GHSA-h9m2-3vjx-c8cq (high): The auto-scaler, manual scale, rolling updates and image updates of stack containers check the stack files like a deploy does, and `.dockmesh.meta.json` and `compose.<env>.yaml` override files count as stack files. A container that can write its own stack directory can no longer have Dockmesh create a container it defined itself without someone confirming the change. Affects v0.5.2 and earlier
- GHSA-6pmw-gcfw-xc5x (high): The setup wizard only opens on an installation without any user account. Before, an installation left without an admin assignment reopened the wizard without authentication after a restart. An installation that has accounts but no admin keeps it closed, and the wizard's setup and restore check this again right before they change anything. Removing the last admin is also refused when every admin holds the role on a narrower scope. Affects v0.4.0 to v0.5.2
- Built with Go 1.27.4, which fixes GO-2026-6859 in the Go standard library

### Upgrade notes

- **Admins:** On the first start, the `.dockmesh.meta.json` and `compose.<env>.yaml` files of existing stacks are accepted as they are on disk, the same way `compose.yaml` and `.env` were when they were first checked; nothing needs to be done by hand. If a container can write its own stack directory, review those files after the upgrade. When a container later changes one of these files, the stack shows Modified outside Dockmesh, the next deploy, scale, rolling update or image update asks for a confirmation, and the auto-scaler pauses the stack with a notice until it is deployed. A stack with a default environment override that was never deployed by hand since 0.5.0 also pauses auto-scaling until it is deployed once <!-- stack-files-backfill -->
- **Admins:** An installation that has user accounts but none with an admin role no longer opens the setup wizard. Its log and a notice show how to get access back: run `sudo dockmesh admin create --username <name> --role admin` on the server and restart the service. Installations with an admin and new installations need nothing <!-- setup-no-admin -->
