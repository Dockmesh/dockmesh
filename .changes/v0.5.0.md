## [0.5.0] - 2026-11-03 [security]

Dockmesh 0.5.0 brings a redesigned web UI with a German translation, roles per area that can be limited to hosts, host tags or stacks, live progress and cancel for long operations, and safer backups with credentials encrypted at rest. It also fixes several scope leaks in earlier releases; see the Security section and the linked advisory. Read the upgrade notes before upgrading: access is migrated to the new role model, and going back needs the database snapshot written before the migration.


### Highlights

- Roles per area with scopes: access is given as assignments of a role on everything, a host, a host tag or a stack, and a role is a level per area (stacks, containers, backups, proxy, users, ...) plus a few risky extras.
- A redesigned web UI, in English and German: dense, sortable tables, dialogs instead of side panels, an Updates page, an activity feed with what needs attention, and a German translation that follows the browser or each user's choice under Account, including alert channels, mail and audit entries.
- Live progress and cancel for long operations: image updates, backups, restores and new proxy sites show their real steps and a live log, keep running when you close the dialog, are listed in the running-operations indicator, and can be cancelled while they run.
- Safer backups: saved targets, credentials encrypted at rest, archives checked against their checksum before a restore, restores that swap in only when complete, one restore per volume at a time, a stall timeout, and system restores from the UI and the setup wizard of a fresh install.

### Added

- Image updates, backup runs, restores and new proxy sites show their real steps and a live log while they run. A running-operations indicator in the top bar lists running and recently finished work and opens its progress from any page; a toast says when your own work finishes, and a failure shows the step it failed at with its last log lines. Operations are kept for 7 days and listed under `GET /api/v1/operations` (live on `/ws/events`); credentials are masked before anything is stored or shown, and you only see operations on hosts and stacks in your scope. Work still running when the server stops is marked failed on the next start.
- An Updates page lists available app image updates next to the Dockmesh, Caddy and agent versions; several containers can be updated at once (`POST /api/v1/containers/updates`), one after another on the server, each with its own progress.
- Every audit log entry has a category (`changes`, `access`, `auth` or `system`), and the audit API filters by it with `?category=`.
- `GET /api/v1/attention` lists what needs attention in your scope: offline hosts, restarting, unhealthy or failed containers, failed backup jobs, firing alerts, proxy certificates expiring within 30 days and open action-required notices. Agents on a different build than the server and available image updates are listed as information. Items are sorted most severe first.
- Alert rules for events: container restart loops, OOM kills, unhealthy containers and unexpected stops (on the server and on agents), offline hosts, disk usage per mount, failed or overdue backups and proxy TLS certificates close to expiry. Rules can be limited to a host, a host tag or a stack and use the existing notification channels. New built-in rules are on for restart loops, OOM kills, offline hosts, disks above 90%, backups and certificates expiring within 14 days; admins of existing installs get a notice listing them. Agents that are too old for container events are listed in a notice too. Users limited to certain hosts can only manage rules restricted to one of their hosts and only see alert history from those hosts.
- Agents renew their client certificate over their existing connection when it has less than 30 days left; the host keeps its ID. Admins get a notice for any agent whose certificate is within 14 days of expiry, and a critical one for an offline agent whose certificate has expired, with the steps to re-enroll it under the same ID.
- The hosts list and host page show "update recommended" for agents that speak an older protocol than the server, and the host page shows when the agent's certificate expires.
- Backup schedules run in the time zone set in `backups.timezone` (an IANA name such as `Europe/Berlin`); without it they use the server's time zone, which the job wizard now shows next to the schedule.
- System backups can be restored from the UI (Backups → a system run → Restore, or "Restore system from file" for an uploaded archive) and from the setup wizard of a fresh install ("Restore from a backup instead"), including encrypted backups together with the key file exported from the original server. The backup is unpacked and checked next to the live files first; the server then restarts and swaps the restored files in before it opens the database. The replaced files are kept in `<data>/.pre-restore/<time>` and `<stacks>.pre-restore-<time>`.
- `GET /api/v1/system/whats-new` returns the release notes of the running version and of a newer release, and `POST /api/v1/system/whats-new/seen` remembers per user that they were read. Changelog sections may start with a `### Highlights` list, which the release notes and `release-manifest.json` now include; the changelog check requires three or four of them in every minor release.
- Proxy routes take per-site options through the API: response streaming, upload streaming, upstream timeouts, a request size limit, keeping WebSockets open across config reloads, compression, several upstreams with load balancing and health checks, a www redirect, serving HTTP alongside HTTPS, HSTS, basic auth, IP allow and deny lists, forward auth, security headers, request and response headers, and an access log. Basic-auth passwords are stored as bcrypt hashes and never returned. `GET /api/v1/proxy/routes/{id}/config` shows the Caddy config a site gets. Users without `proxy.update` see header values masked and the forward-auth URL without its query. Existing routes keep their current behaviour.
- `POST /api/v1/proxy/import` reads a Caddyfile and creates its sites as disabled proxy routes with the matching options. Directives without a matching option are listed per site instead of being dropped, and `dry_run` shows the result without creating anything. Snippets defined in the same file can be imported; imports of files can't.
- The Caddy version of the proxy can be switched between the versions tested with this release (`/api/v1/proxy/version`), with a rollback to the previous one. A version that doesn't come up with the current config is rolled back automatically. While `DOCKMESH_PROXY_IMAGE` is set the version can't be changed.
- Proxy settings for the ACME account email, the certificate authority (Let's Encrypt, its staging environment, or ZeroSSL) and trusting Cloudflare as a proxy in front of Caddy (`/api/v1/proxy/settings`). Both need `proxy.update` to change; users without it see the ACME email with its local part hidden.
- Reverse proxy sites have their own page with traffic, certificate, activity and config preview
- Activity page with what needs attention and the notification history; the bell shows the latest notifications and counts unread ones
- User detail pages with access, sessions and 2FA, API tokens and activity; role detail pages with the level matrix; an access check that names the assignment that allows an action
- Identity provider group mappings take a scope, and every matching group adds its role
- API tokens can be restricted to a role on a scope; a token always follows its owner's current access
- The host page charts CPU, memory and disk over time (live up to 30 days) and lists the containers using the most CPU or memory. Agents record host and container history too and send it to the server every minute, also catching up after a short disconnect; agents older than this release keep working with live values only
- The backup job wizard picks the host: volume jobs choose a host and one of its volumes, stack jobs run where the stack is deployed, and only hosts where you may manage backups are offered. Saving checks that the host, volume or deployment exists.
- Proxy sites have an Options tab to edit routing, HTTPS, performance, access, headers and logs, with a warning on risky settings and server errors shown next to the field; the new-site dialog has an optional Advanced step with the same groups, and a Config tab shows the Caddy config the saved site produces. Header values can be marked secret, and secret values, basic-auth passwords and the forward-auth query are write-only: never shown again, kept when left empty, and hidden from the config preview for everyone. Site changes are audited with the option groups that changed.
- Running work can be cancelled from its progress dialog and the backup and update lists: a backup run in any step (post-backup hooks still run and the unfinished archive is deleted from the target), an image update while it pulls, a restore while it downloads or verifies the archive, and the certificate wait of a new proxy site (the site stays). The operation ends cancelled and names the step it stopped in; cancelling needs the permission that started the work.
- The container Files tab works on agent hosts too: browse, preview, download, edit and upload, plus deleting a file or symbolic link on every host. Uploads are limited to 8 MiB, previews and edits to 1 MiB, and /proc, /sys, /dev and device files can't be opened, also behind a bind mount of the host's /proc. Files of Dockmesh's own containers and of containers with the Docker socket are not accessible. Agents older than the server ask to be updated.
- Container CPU and memory alert rules cover every host, agents included, and can be limited to a host or a host tag like the event rules.
- Creating a stack asks which host it is for (`host_id` on `POST /stacks` and `/stacks/from-git`). Until it is deployed the stack belongs to that host, so a user whose access is limited to some hosts can read, edit and deploy the stacks they create there.
- Admins see another user's sign-in sessions on the user's Sessions & 2FA tab and can end one or all of them (`GET /api/v1/users/{id}/sessions`).
- The access check on the user page also answers for every host with a tag (`host_tag` on `POST /api/v1/access/check`).
- Add host and Settings check the agent URL from the server and explain split DNS, closed ports and proxies that terminate TLS
- Admins are told about the files a system restore kept from before the restore and can delete them on the Backups page.
- Delete a stack from the row menu of the stacks list, with the same cleanup choices as on the stack page.
- API errors carry a stable `code` next to the English `error` text, and `PUT /api/v1/me/language` sets the signed-in user's language (`en`, `de` or empty for the browser language).

### Changed

- Sizes follow Docker's units everywhere: images, files, disks, transfers and backups in kB, MB and GB (base 1000), memory and memory limits in KiB, MiB and GiB (base 1024).
- The overview lists the five most severe items that need attention; "+N more" opens the full list with a severity filter.
- The reverse proxy container Dockmesh runs for itself is marked System in the containers list and its detail page shows it read-only, with a link to the Reverse proxy page.
- Users with `alerts.view` can open the Alerts page and read rules, channels and history; creating, editing and deleting follow `alerts.create`, `alerts.update` and `alerts.delete`.
- A single image update keeps running when you close the page while it pulls or swaps the container.
- The Files tab of a container on an agent host says that browsing files is available for containers on the server host only, instead of showing an internal error.
- The overview, hosts, alerts, backups, stack detail, reverse proxy and setup pages follow the new design. The overview lists what needs attention and the recent changes from the audit log; alert rules are edited in a dialog that adapts to the rule type and says in a sentence when the rule fires; the reverse proxy page can import a Caddyfile and switch the Caddy version and proxy-wide settings; revoking a host asks you to type its name.
- New look for the web UI: a calmer, flat design with equal light and dark themes that follow the system setting until you pick one. The sidebar is grouped into Workloads, Infrastructure, Operations and Admin, shows counts, and collapses to an icon rail. Authentication, registries and the global environment now sit under Settings with their own sub-navigation. Ctrl+K (⌘K) searches pages, stacks, containers, hosts and settings.
- Stacks, containers, templates, resources, topology and settings follow the new design. The containers list can be grouped by host or by stack, the container page shows CPU, memory, network and disk I/O history in charts with zoom and deploy markers, and CPU is shown as a share of all host cores. New templates list the placeholders found in the compose file so you can label them and set defaults. Settings are split into General, Updates and Encryption key.
- Updating the image of a container that belongs to a stack now rebuilds it from the stack's compose.yaml, together with the other replicas of its service, and records the new image in the stack's deploy history. Because that applies the stack's current compose.yaml, it also needs the `stacks.deploy` permission.
- Only the newest three rollback images per image tag are kept after an update (`DOCKMESH_UPDATE_ROLLBACK_KEEP` changes the number).
- Update checks for private images use the credentials saved under Registries, and an update that was already announced isn't announced again after a restart.
- The proxy now runs a pinned Caddy version (2.11.7, pinned by digest) instead of whatever `caddy:2` pointed to; set `DOCKMESH_PROXY_IMAGE` to use another. The proxy container is recreated once after this upgrade and then kept across Dockmesh restarts instead of being replaced on every start.
- Proxy route upstreams must be `host:port` and may not point at the proxy's own admin API, and a route's host may not be `localhost`, a loopback address or a bare `*`. Existing routes that break these rules stop being served and are listed in a notice for admins.
- Updated the bundled libraries, including the Docker SDK (28.5), SvelteKit 3 and Vite 8.
- The dashboard and host page now list disk usage for every real filesystem of a host, with the mounts holding Docker, containerd, stacks, Dockmesh data and local backups labelled. The host's disk figure now shows the fullest of the Docker-related mounts instead of the data directory only, so a full Docker or containerd mount no longer goes unnoticed. Hosts with an older agent keep the single figure until the agent is updated.
- Backup jobs now write to saved backup targets instead of keeping their own copy of the target settings. On upgrade, each job's settings are moved to a saved target named after the type and server (for example `sftp-nas.lan (migrated)`); jobs with the same settings share one target, and a job that already matches a saved target uses it. A new target set up in the job wizard is saved under the job's name. Editing a target shows how many jobs use it, and a target that jobs still use can't be deleted.
- "Run now" starts the backup in the background and returns at once; closing the browser no longer cancels it. A job that is still running is not started a second time, and a scheduled run is skipped (with a notification) while the previous one is in progress.
- S3 backups stream to the bucket instead of being written to a temporary file first.
- Restoring a volume or stack backup puts the volumes back on the host the backup was taken on (or one you pick), instead of always on the central server. The archive is checked completely before anything is overwritten, and you choose between replacing the volume's contents (refused while containers use it) and merging. A volume that fails to restore now fails the stack restore instead of being reported as a warning. Restoring a stack under another name gives the copy its own volumes instead of writing into the original stack's. Restoring onto a remote host needs the agent from this release.
- A restore downloads the archive once, checks it against the recorded checksum, verifies it and restores from that same copy. Only one restore at a time may write a given volume or stack, at most two restores run at once, and replacing a volume's contents needs a backup with a recorded checksum (older backups can still be merged). Restoring a stack as a copy under another name leaves volumes with a fixed name alone and lists them in the result.
- `dockmesh restore` uses the same staged swap: a restore that stops halfway no longer leaves stacks and data overwritten next to the old database, and it finishes on the next start. It takes `--key` for encrypted archives; `--skip-sanity` is gone, the checks always run.
- One design language across all pages: round status dots, one status per row, sentence-case status chips, monospace only for technical values
- Audit log redesigned with categories, a user filter, links to the changed objects and an entry dialog
- A notice shown in the banner no longer also appears in Needs attention; a dismissed notice moves there until it is resolved
- Side panels are gone: forms and confirmations open as dialogs, operation progress opens as a dialog you can close while the work continues
- Host switcher with search, tags and keyboard selection; new Dockmesh logo and favicon
- Proxy, alert rules, users and roles, settings and the audit log need an assignment on everything; a narrower assignment never grants them
- Viewing logs is part of View; environment values in inspect and .env need Deploy on the stack or the env extra
- Container and host charts show CPU as a share of the whole host, memory without page cache (as docker stats shows it on cgroup v2), and say when a container has no memory limit
- API: GET /containers/{id}/metrics and GET /hosts/{id}/stats/containers return an object with host_id, history and the samples instead of a bare array; cpu_percent is now 0-100 of the host, cpu_percent_core keeps the per-core value; new GET /hosts/{id}/metrics
- Container files need the files extra on the container's host or stack; uploading, editing and deleting need the terminal extra as well. Roles with only the terminal extra no longer see the Files tab.
- When a rule fires for many targets on one host at once, its channels and the bell get one message ("12 containers on dm-agent1") instead of one per target; the resolved message is grouped the same way.
- CPU alert rules and autoscaling rules state their unit: "% of host", the share of the whole host the charts show and the default for new rules, or "% of one core" (100 per busy core, as docker stats shows it). The API field is `cpu_unit`.
- Opening a page your roles don't allow shows a no-access message instead of a page full of permission errors.
- Running and restoring a backup are audited as `backup.run` and `backup.restore` instead of `stack.deploy` and `container.rollback`.
- `dmctl backup run` waits until the run finishes and exits non-zero when it failed; `--no-wait` returns once it started.
- Needs attention no longer lists announcements, and agents on a different build show as one item.
- Successful backup runs no longer send a notification; they are listed under Activity.
- Redesigned sign-in page with its own two-factor step, a session-expired notice and the password reset command; the unused Remember this device box is gone.
- The audit log and Recent changes read as sentences and show user and host names instead of ids.
- The operation dialog explains common errors such as a full disk or a folder Dockmesh can't write, and no longer repeats the failure in a toast.
- The browser tab icon follows the light or dark system theme.
- The banner only shows notices about something that stopped working; you can hide one for 24 hours and it comes back while the problem lasts. Everything else is listed under Needs attention.
- Never-deployed stacks show as Not deployed, Stop only shows while something runs, and the sidebar Stacks count follows the host filter.
- Settings & audit has a new **Metrics** level below View that grants only the Prometheus `/metrics` scrape, so a scrape token no longer needs access to the audit log. Roles with Settings & audit: View keep the scrape.

### Fixed

- The setup wizard proposes `/var/lib/dockmesh` as data directory instead of `/data`, which a native install cannot write; it shows the install log and the sign-in even when the install finishes before the page connects to it, reports a synchronised clock as synced on current systemd, and its last step says whether the install finished or failed.
- Users limited to some hosts no longer get an error from the stack page while a newly created stack is not deployed yet.
- Upgrading an agent that already runs the server's build answers 409 with an explanation instead of 500.
- Proxy routes in the API list empty options as `[]` instead of `null`, and a newly created route is returned with its real creation time.
- The stack page offers switching overlays and editing dependencies only with `stacks.deploy`, which the server requires.
- Users limited to some hosts no longer see every enrolled agent, other users' audit entries or the server's image update checks, and can no longer rotate the token of, upgrade or revoke an agent outside their scope tags. Their overview no longer shows 0 of 0 hosts and their stacks as stopped when their scope leaves out the server host.
- Backup jobs, runs and saved targets of hosts outside a user's scope are no longer listed or readable, and the system backup job and its runs are shown to admins only. Before, everyone with `backups.view` saw every job and run, including their errors, and users limited to some hosts saw a failing server backup in their overview. The system backup's last error in the sidebar status is shown to admins only, and testing or deleting a saved target now needs access to every job that uses it, like editing it.
- An image update whose pull fails inside Docker's progress stream (rate limit, missing credentials, unknown tag) now fails instead of reporting the container as already up to date.
- Backup hook output in the run log no longer starts every line with stray characters.
- The last setup step showed a made-up password when the page was reloaded there; it now refers to the password you entered.
- `dockmesh-agent --version` works for users other than root. The installer now puts a root-owned copy of the agent in `/usr/local/bin` instead of a symlink into the agent's data directory, and the agent's service refreshes that copy at every start. Agents installed earlier still have the symlink: after upgrading to this release they make the data directory traversable (not listable) and remove group and other access from everything else in it. Re-running the agent install command is optional and replaces the symlink with the copy and closes the data directory again.
- Versions are no longer shown as "vv0.4.2" on the host pages and in the host switcher.
- The disabled OIDC option in the invite dialog explains that SSO users get their account at their first sign-in, instead of showing an internal note.
- The resources page no longer fails to load when images have never been scanned.
- Logs and terminal links in the containers list open those tabs instead of the overview.
- Updating a proxy route without `enabled` no longer switches a disabled route back on, and the update returns the saved route.
- Updating a container's image no longer loses its anonymous volumes (`-v /data` or a `VOLUME` in the image); the new container gets the old volumes.
- A failed image update no longer leaves the container deleted: the old container is kept until the new one runs, and is started again if the new one fails. The previous image stays tagged for a rollback.
- Locally built images no longer always show "update available".
- Proxy routes keep working after the Caddy container restarts; before, it came back with no routes until Dockmesh pushed them again.
- Proxy routes with TLS set to "none" are now served over plain HTTP instead of getting a certificate and an HTTPS redirect anyway.
- Coming back to an idle browser, or having Dockmesh open in several tabs, no longer signs you out. Tabs now share one session renewal, and a short network outage while renewing keeps you signed in and retries instead of returning you to the sign-in page. Container file downloads now renew an expired session like every other request.
- The volume detail page no longer reloads endlessly when the volume does not exist; it shows an error instead.
- Leaving a stack page during a migration stops its status polling.
- The host detail page now loads the new host when you switch between hosts.
- Starting and stopping stack operations updates the busy state of every open stack page.
- Switching hosts no longer loads the dashboard, containers, stacks and resources pages twice, and a slow response for the previously selected host can no longer overwrite the new one. Auto-refresh skips a cycle while the previous one is still loading.
- Leaving a container or stack page while its logs, stats or terminal are connecting no longer leaves a socket open in the background.
- Container CPU and memory alerts now fire once a breach has lasted for the rule's duration (allowing for one missed sample) and resolve only after the value has been back to normal for a full sampling interval, so they no longer stay silent or flap. Cooldown and "muted until" are honoured, muted rules no longer send "resolved" messages, and the rule statistics count fires correctly.
- Notification channels retry a failed delivery twice before giving up, and the last delivery error is shown on the channel card. Toggling a channel on or off no longer clears its quiet hours.
- Deleting a host while one of its shells, log views or requests was open no longer crashes the server, and the deleted host's connection is closed right away.
- Remote deploys, scale-ups and backup pre-hooks on agents are no longer cut off after 30 seconds; they get time for image pulls and database dumps, and a cancelled request now also stops on the agent.
- Requests to a host that just reconnected go to the new connection instead of hanging on the old one.
- Remote volume exports (used by multi-host backups) slow the agent down instead of silently dropping data when the server reads slower than the agent sends, and report a failing `tar` as an error. Closing a remote shell no longer leaks a goroutine.
- Agents notice a vanished server within 90 seconds, reconnect immediately and then back off with jitter, and no longer leak a goroutine on every stack request.
- Backup retention only deletes archives recorded for the job's own runs instead of listing the target, and never the newest archive of a job. New archives go to a folder named after the job ID; existing archives are still managed where they are.
- A failed backup run deletes its partial archive and is no longer counted by retention, so a few failed runs can't push the last good backups out.
- A stack backup fails when the compose file can't be read or one of the stack's volumes can't be archived, instead of reporting success without that volume. Local volume archives fail when `tar` exits with an error.
- Verifying a stack backup checks that every volume the stack had is in the archive.
- A failing post-hook marks the run "completed with warnings" instead of failed; the archive can still be restored. Post-hooks also run when a later pre-hook or the upload fails, so a service stopped by a pre-hook is started again.
- Deleting a backup job keeps its runs restorable; runs whose archive was removed by retention are shown as pruned.
- A backup run whose request is cancelled midway still records its result instead of staying "running".
- Backup runs that were still running when the server stopped are marked failed at the next start instead of showing "running" forever.
- Volume backups no longer keep a copy of the archive in Docker's container log of their helper, which took several times the archive's size on the server's disk while the backup ran. A backup that fails midway stops and removes its helper container instead of leaving it running until the next restart.
- Users with view access to backups can open the Backups page; each action is offered only with its permission
- Agent branch builds are no longer labelled as patch updates
- With the host filter on one host, Overview and Stacks list and count only that host's stacks instead of showing other hosts' stacks as stopped
- The Add host dialog keeps keyboard focus inside while it is open
- Users limited to a host no longer see stacks that are not deployed anywhere
- OIDC sign-in applies the group mappings saved in the provider form, not only the old admin and operator group fields
- Host disk usage follows a custom Docker data-root instead of always measuring /var/lib/docker
- Container history at the 1-minute and 1-hour resolutions (7 and 30 day ranges) no longer fails for containers whose average memory was not a whole number of bytes
- A backup run whose target or source stops moving data now fails after 10 minutes with "target stalled" and frees the job, instead of holding its run slot until the server restarts. This includes SFTP targets, which had no idle limit and hung for good on a server that stopped answering.
- Restoring a volume with mode replace extracts into a staging directory inside the volume and swaps the old contents out only after the archive extracted completely; a broken agent stream, a failing tar or too little free space leaves the volume as it was. The free space for old and new contents side by side is checked before anything is written.
- Alert history is pruned after 30 days (an alert that is still active keeps its entry), OOM kills and failed backups that repeat inside the rule's cooldown are counted on one entry instead of adding new ones, and a rule tracks at most 500 targets per host, so a noisy or misbehaving agent can no longer grow the database and server memory without bound.
- Host-scoped users get bell notifications for alerts on their hosts and no longer see CVE-scan and image-update notices of the server; alert history returns up to the requested number of entries from the caller's hosts, and an admin on everything who also holds a narrower assignment keeps the full alerts view.
- Audit entries written by an API token name the token's owner and the token, instead of showing up as "system".
- The certificate warnings on the overview no longer stall when many proxy sites point at unreachable hosts: certificates are checked in the background, a few at a time, and an unfinished check isn't cached.
- Deploying with an environment override now resolves global environment variables in the override merge.
- Syncing or removing a stack's copy on an agent host no longer fails when the request that triggered it finishes first.
- Agent install commands and the agent certificate now use the URL from the setup wizard and the Settings page instead of localhost; dockmesh.env still wins
- systemctl stop and restart of dockmesh-agent return in seconds instead of hanging until systemd kills the agent after 90 s
- Reinstalling over a kept data directory or into a different install directory reuses the existing dockmesh.env instead of rewriting it
- A failing upgrade after restoring a backup now keeps a pre-migration copy of the restored database instead of reusing an older snapshot
- Deleting a stack also deletes its git source and clone, so a new commit no longer brings the deleted stack back.
- A git source poll interval of 0 turns polling off (webhook or manual sync only) instead of becoming 300 seconds.
- Updating a standalone container takes the new image's default environment, command, entrypoint, working directory, user, labels and healthcheck instead of keeping the old image's; values set on the container itself are kept.
- Registry credentials with scope tags now apply to hosts carrying those tags, and deploys, scaling and scale checks on agent hosts send the credentials for their images, so private images work there without pre-pulling.
- A stack migration that fails while stopping the source or syncing now restarts the stack on the source host, and a failed start on the target stops what was started there before the source comes back.
- Git auto-deploys run on the host the stack is deployed on (or was created for) instead of always on the server, record the deployment, apply global variables and the default environment override, and force a fresh pull on agents too.
- Who may read or restore a backup run, and where a restore goes by default, follows the host the run was taken on, not the host its job was moved to later.
- The MySQL and MariaDB hook presets work: wizard hooks run through `sh -c`, and the dump presets write into the database's data volume instead of `/tmp`.
- Saving a job in the wizard keeps its custom pre-hooks and its post-hooks; both can be edited there.
- The job wizard sends the SFTP port as a number and offers the SFTP private key and the S3 prefix and TLS switch for inline targets.
- Download key backup on the encryption settings page works; it used a plain link that carried no session token.
- The Prometheus gauges dockmesh_backup_last_run_timestamp_seconds and dockmesh_backup_last_duration_seconds are filled again.
- A local backup target without a path writes to <data directory>/backups instead of a directory relative to the server's working directory.
- Creating, changing or deleting a backup job, adding or removing a host, upgrading an agent and draining a host were recorded in the audit log as stack actions.
- The new proxy site dialog suggested container names, which Caddy can't reach from the host network; it now offers published ports on localhost.
- The Authentication page and the provider dialog show the callback, ACS and metadata URLs the server really sends to identity providers (built from `DOCKMESH_BASE_URL`) and warn while it is unset. New providers from a template get the plain provider name as button label, no prefilled example issuer, and the Keycloak template no longer asks for a `groups` scope the realm may not have.
- OIDC and OAuth2 scopes are accepted separated by spaces or commas and stored space-separated. `uninstall.sh` stops only the server process in `DOCKMESH_INSTALL_DIR`, not a `dockmesh-agent` started from the same directory.
- Volumes are created and deleted on the host they belong to. Before, both always acted on the server's host, so deleting a volume listed for an agent host removed a server volume of the same name. Network rows of agent hosts open their network page. Agents need this version to create or delete volumes.
- The restore progress dialog opens the restore you just started, not an earlier restore of the same backup run from the last minute.
- Deploying, stopping, scaling or rolling back a stack from its page while the host picker showed another host, or through the API without `host`, ran it on that other host (usually the server) and started a second copy with empty volumes. These actions now go to the stack's own host, and the API refuses another host with 409 `stack_on_other_host`; Migrate moves a stack.

### Security

- A rollback now only accepts update-history entries of the container it is called for, and the update history is limited to containers in the caller's scope. Before, a user scoped to one stack could roll back containers of other stacks.
- A proxy route can no longer forward to the proxy's own admin API, which would have let anyone reaching the proxy change its configuration. The admin API now also refuses requests from browsers on other sites.
- Restoring a stack backup writes that stack's compose file and environment, so it now needs the "Edit stacks" permission ("Create stacks" for a new name), the stack within your role scope, and the host the stack is deployed on within your scope. Before, `backups.restore` on the backup's host was enough to overwrite or create any stack, also for users limited to certain hosts.
- Dockmesh's own containers (the server when it runs in a container, the reverse proxy, agents and helpers) can only be stopped, removed, updated or opened in a terminal by an admin, and backup hooks can't run in them; the file browser is closed for them. The proxy's config and certificate volumes and an agent's volume can only be browsed or backed up by an admin, since they hold TLS private keys and proxy credentials.
- Scope fixes: an open live-events connection follows role and scope changes instead of keeping the access it started with; the status and deploy progress of an undeployed stack, the adoptable-project list and the network topology only show what is in your scope; a stack name that a stack assignment names can't be taken by a user limited to some hosts.
- An API token created with another API token never holds more than that token holds at the time of use, and stops working when that token is revoked or expires.
- Users who may view but not edit proxy sites see the forward-auth URL as `scheme://host:port`; a token in its path is no longer shown.
- Creating a stack from a git repository refuses a name that already belongs to a stack, instead of replacing that stack's files from the repository; template deploys and adoption also refuse existing and reserved names, and a compose project that runs Dockmesh itself can only be adopted and changed by an admin.
- Global environment variables marked secret are now stored encrypted. Before, only the API hid their values; the database held them in plaintext. The create form and the .env import can mark variables as secret, and a secret can no longer be turned back into a plain variable by editing it.
- Deploy history of stacks deployed with an environment override no longer contains the stack's .env values. History keeps the base compose file and the override name; a rollback applies the override again.
- Backup target credentials (SMB, SFTP and WebDAV passwords, S3 secret keys, SFTP private keys) are now stored encrypted with the server's secrets key. Before, the database and every system backup held them in plaintext.
- OAuth2 and LDAP accounts are keyed by the provider's immutable user id (the userinfo `sub` or `id`, `objectGUID` or `entryUUID`) instead of the username field or the DN, so a renamed GitHub-style login or a moved directory entry that someone else takes over no longer signs into the old account. New **Subject field** (OAuth2) and **Subject attribute** (LDAP) options choose another id.
- Deleting an SSO provider unlinks its accounts, and pointing a provider at another identity provider (a different OIDC issuer, SAML IdP entity, OAuth2 userinfo URL or subject field, or LDAP server or subject attribute) unlinks them on save, so a provider that reuses the slug or the new IdP can't sign into accounts of the old one. The provider dialog warns before saving such a change.
- Stack migrations refuse compose.yaml or .env files changed outside Dockmesh until you confirm them, like a deploy does, and the target gets the global variables and the default environment override.
- A git sync no longer copies `.dockmesh.meta.json` or `compose.<env>.yaml` override files from the repository, so a repository push can no longer replace migration hooks, scaling rules or the default environment override of a stack.
- The backup target the audit log is archived to is hidden from non-admins, and only admins can change, delete or pick it for a job.
- Restoring a backup into one of Dockmesh's own volumes (the proxy and agent volumes, or any volume the server, proxy or an agent container mounts) is refused for non-admins.
- Changing or running the agent upgrade policy needs Hosts: Manage on everything; a grant on some hosts or tags could set fleet-wide auto-upgrade before.
- The old enrollment route `POST /api/v1/agents/enroll` on the HTTP port is gone (it answers 410). It handed out an agent's key and certificate over whatever reached the HTTP port, plain HTTP included; the install command has enrolled on the agent port since v0.4.0.
- `install.sh` installs a pinned Grype release and checks its SHA-256 before installing it, instead of running Anchore's install script from their main branch as root.
- The Redis template turns on password auth with a generated password and publishes the port on `127.0.0.1` by default (new `bind_address` parameter). Before, it ran without auth on every interface unless you typed `--requirepass` into the password field. Stacks already deployed from it are unchanged.

### Upgrade notes

- [review-access, admins] Users, roles, scopes, tokens and invites migrate automatically and never gain access; where the old setup can't be expressed exactly, access is narrowed and an admin notice lists every account, role and token that changed. Review it under Users & roles
- [builtin-roles, admins] The built-in roles follow the new definitions: Operator no longer deploys, Deployer no longer deletes stacks or opens terminals, Viewer can read logs; DOCKMESH_RBAC_V2_ENFORCE is gone. The admin notice after the upgrade lists everything each role lost
- [update-agents, admins] Container metrics are moved to a layout keyed by host on the first start, keeping every sample. Update agents to record history on their hosts; until then their charts show live values.
- [proxy-forward-auth-query, admins] API responses no longer include the query of a proxy site's forward-auth URL, also for users who can edit the proxy. Clients that send the URL back without a query keep the stored one; nothing else changes for existing sites.
- [restore-replace-agent, admins] Restores with mode replace onto a host behind an agent need the agent of this version; an older agent is refused with a message to upgrade it from the Hosts page. Merge restores keep working with older agents.
- [cpu-unit, admins] Existing CPU alert and autoscaling rules are labelled "% of one core" and behave as before; edit a rule to switch it to "% of host". API clients that create alert rules or write scaling rules without `cpu_unit` get "% of host".
- [scope-auth, admins] API tokens created with a token before this release have no parent on record and keep working as before. Stacks created before this release have no host until they are deployed; users limited to some hosts need an admin to deploy them or to give them a stack assignment. Backup jobs with hooks into Dockmesh's own containers keep running; review them under Backups.
- [secrets-at-rest, admins] On the first start, stored backup target credentials and secret global variables are encrypted automatically. Deploy history entries of environment-override deploys made before this version lose their compose snapshot, because it held .env values; they can no longer be rolled back to. Stacks whose compose.yaml an earlier rollback filled with .env values get a notice. The database snapshot taken before the upgrade (*.pre-migrate-*.bak next to the database) still holds the old plaintext values; delete it once the upgrade works.
- [sso-rekey, admins] Existing OAuth2 and LDAP accounts move to their immutable id at their next sign-in within 30 days of the upgrade, as long as the login name or DN is still the one they were linked with; when that key isn't the new id (a GitHub `login`, a DN), the e-mail at the provider has to match the account too, and accounts with two-factor authentication or a role that manages users or settings are then left for an admin to recreate. Users renamed or moved before signing in again, and accounts not signed in within the 30 days, can't sign in through their provider any more and have to be recreated. The Authentication page and an admin notice list the accounts still waiting, with **End re-keying** to stop. Links left behind by providers deleted on earlier versions are removed.
- [agent-url-setting, admins] Without DOCKMESH_AGENT_PUBLIC_URL in dockmesh.env, install commands now use the agent URL from Settings, or the base URL's host on port 8443, and the agent certificate gets that name added on the first start. Existing names and IPs stay, so enrolled agents keep connecting.
- [agent-registry-auth, admins] Registry credentials now also reach agent hosts for the images they deploy; a registry without scope tags applies to every host, so add scope tags to registries that must stay off some hosts. Agents need this version to use the credentials; older agents keep pulling anonymously.
- [git-poll-zero, admins] Git sources saved with poll interval 0 before this version were stored as 300 seconds; set 0 again to turn polling off.
- [git-override-confirm, admins] Git auto-deploys and migrations now apply the stack's default environment override, but only one a manual deploy used with the same file; deploy a stack with an override once by hand to confirm it.
- [audit-backup-actions, admins] Backup runs and restores are now audited as backup.run and backup.restore; update audit webhooks or SIEM filters that matched stack.deploy or container.rollback for backups.
- [audit-job-host-actions, admins] Backup job changes, adding or removing hosts, agent upgrades and host drains are now audited as backup.job_create/update/delete, agent.create/delete/upgrade and host.drain/drain_abort instead of stack actions. Audit webhook filters that relied on stack.* for these need backup.*, agent.* or host.* added.
- [ui-language, all] Browsers set to German now show the UI in German. To keep English, choose English under Account → Language; the choice is saved per user. Alert channels keep sending in English until a language is set on the channel.
- [downgrade, admins] Going back to v0.4.2 by putting only the old binary back is not supported after this upgrade; v0.4.2 does not start on the migrated database. To roll back, restore the previous binary together with the database snapshot written before the migration (`dockmesh.db.pre-migrate-*.bak` next to the database), as described under Upgrade, Rolling back.
- [upgrade-agents, admins] Upgrade agents after the server, from the Hosts page or with the agent upgrade policy. Older agents keep running, but replace restores, host-side volume changes, registry credentials and metrics history on their hosts need this version.
